# Sean's edits (Claude session, 2026-04-30 → 2026-05-02)

## 1. MMseqs2 `--split-memory-limit` support

Adds CPU-RAM cap so MMseqs2 splits the DB into chunks that fit in budget,
instead of loading the full DB at once → fixes OOM on large DBs (uniref90,
uniprot, etc.) even for tiny query sequences.

**New config field** — `MmseqsConfig.split_memory_limit: str | None`
- `src/alphafold3/data/msa_config.py`

**New ctor arg** — passed to `mmseqs search --split-memory-limit <val>`
- `src/alphafold3/data/tools/mmseqs.py` (`Mmseqs.__init__`, `_run_search`)
- `src/alphafold3/data/tools/mmseqs_batch.py` (`MmseqsBatch.__init__`,
  `MmseqsMultiDBBatch.__init__`, both `_run_search` cmds)

**Plumbed through pipeline**
- `src/alphafold3/data/pipeline.py`: `DataPipelineConfig.mmseqs_split_memory_limit`;
  forwarded to all 4 `MmseqsConfig(...)` instantiations (uniref90/mgnify/small_bfd/uniprot)
  + RNA `MmseqsConfig` + `MmseqsBatch` + `MmseqsMultiDBBatch`
- `src/alphafold3/data/msa.py`: forwarded in all 3 `Mmseqs(...)` call sites
  (single-DB, sequential, `get_msa_shared_db_pipelined`)

**CLI flag** — `--mmseqs_split_memory_limit`
- `run_data_pipeline.py`: default = ~50% of currently-available RAM
  (computed via `/proc/meminfo` `MemAvailable`, falls back to `SC_AVPHYS_PAGES`).
  Empty string → disables (use MMseqs2 default).
- `scripts/run_alphafast.sh`: forwards as `--mmseqs_split_memory_limit=...`
- `scripts/run_multigpu.sh`: env-passes `MMSEQS_SPLIT_MEMORY_LIMIT`

## 2. `--lowram` flag

Disables pipelining: `result2msa` for DB N completes before search of DB N+1
starts. Caps peak RAM at one DB at a time. Slower but safer.

- `DataPipelineConfig.low_ram: bool = False` (`pipeline.py`)
- `_get_protein_msa_and_templates(..., low_ram=False)` (`pipeline.py`)
- `msa.get_msa_shared_db_pipelined(..., low_ram=False)`
  → blocks `msa_result_future.result()` before next iter
- `MmseqsMultiDBBatch.__init__(low_ram=False)` +
  `search_all_databases_pipelined` blocks `pending_futures[db_name].result()`
  before next search
- CLI: `run_data_pipeline.py --lowram`
- Bash: `scripts/run_alphafast.sh --lowram`, `scripts/run_multigpu.sh`

## 3. JSON null semantics for MSA / templates

**Original AF3:** `null` and key-absent both → search. `""` → skip.

**AlphaFast change:** distinguishes key-present-with-null from key-absent.
- `unpairedMsa: null` → `""` (skip search, use empty MSA)
- `unpairedMsa` absent → `None` (search, AF3 default)
- Same for `pairedMsa` and `templates` (null → `[]`, absent → `None`)

`src/alphafold3/common/folding_input.py`: `ProteinChain.from_dict` and
`RnaChain.from_dict` parsers updated.

## 4. Template / MSA branch logic refactor

`pipeline.py` `process_protein_chain` rewritten so user-provided templates
are respected end-to-end (PDB search **and** Foldseek skipped).

Decision matrix:
| `has_unpaired_msa` | `has_templates` | Behavior |
|---|---|---|
| F | F | Search MSA + templates (PDB) + Foldseek + merge |
| F | T | Search MSA only; use `chain.templates` as-is |
| T | F | MSA from input; search templates + Foldseek + merge |
| T | T | Use both as-is, no search |

Partial MSA (only one of unpaired/paired) → `ValueError` early.

Same fix applied to **batch path** (line ~1665) — was overriding user
templates with searched + foldseek-merged ones.

## 5. Container source-mount workflow

`scripts/run_alphafast.sh` (singularity branches) bind-mounts host repo
into container at `/app/alphafold`:

```

```

Lets host edits take effect without rebuilding the `.sif`. Caveat: pickles
generated by `uv run build_data` are not in the host tree, so they were

## Usage

```bash
./scripts/run_alphafast.sh \
  --weights_dir /path/to/weights \
  --container /path/to/alphafast.sif \
  --db_dir /path/to/db \
  --output_dir /path/to/out \
  --input_dir /path/to/in \
  --lowram \                              # serialize search + result2msa
  --mmseqs_split_memory_limit 8G          # override default (~50% avail RAM)
```

JSON shortcuts:
- Skip MSA: `"unpairedMsa": null, "pairedMsa": null` (or `""`)
- Skip templates: `"templates": null` (or `[]`)
- Custom templates: `"templates": [{"mmcifPath": "...", "queryIndices": [...], "templateIndices": [...]}]`
